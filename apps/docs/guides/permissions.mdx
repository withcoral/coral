## Overview

In Coral, you decide how users and agents access tools. You do this in three ways:

- Assign [roles](#user-roles) to users.
- Set a [policy for each tool](#tool-policy).
- Choose how to store and configure [provider credentials](#provider-accounts).

A user with a role in a workspace can use that workspace's providers. Depending on each provider's configuration, a user uses their own account for the provider, or shared credentials that the workspace owner configured.

[Agents](#agent-identities) have their own identity, separate from users. They can have their own credentials to connect to providers. You can suspend or revoke an agent's access to Coral.

You can set a policy of **Allow**, **Ask** or **Block** for each tool in a workspace. When a tool uses [approvals](#approvals), a person must approve each call that comes through MCP.

## User roles

A user in Coral can have different roles. Each role allows certain actions.

## Provider accounts

When a workspace owner sets up a provider, they choose its [account setting](/guides/concepts#account-setting):

- **Shared account**: The provider uses a single account. All users and agents in the workspace use that account to call the provider. This setting suits credentials such as service accounts or API keys, whose identity is not tied to one user or agent. Everyone who uses the provider's tools sees and works on the same data.
- **Individual account**: Each user or agent connects their own account and uses it to call the provider. Prefer this setting for providers that use OAuth or personal access tokens, where the credential is tied to the user's identity. Each user or agent works on the data that the provider allows for them.

<Note>Only workspace owners can set up and manage the credentials of shared accounts.</Note>

## Agent identities

Workspace owners can create agent identities. With an agent identity, an agent uses Coral through MCP without Coral's user authentication. Coral creates an API key for each agent, and you set up your MCP client to use that key. You can suspend an agent temporarily, and you can set an expiry for its credentials.

You can set up [individual accounts](#provider-accounts) for an agent, separate from the accounts of your own user. The [tool policies](#tool-policy) that the workspace owner set still apply to every tool call that an agent makes.

## Tool policy

You can set a policy for each tool that users and agents can call. The policy decides if Coral always allows calls to the tool, always blocks them, or asks a person to approve them. Set each tool's policy on the provider's page in your workspace:

- **Allow**: All users and agents in the workspace can call the tool.
- **Ask**: A person must confirm each call to the tool.
- **Block**: No user or agent in the workspace can call the tool.

### Approvals

When a tool's policy is **Ask**, Coral asks a person to confirm each call to the tool. Depending on your MCP client, it displays or opens a Coral URL where you can confirm the request. The Coral UI shows all the details of the tool call, so you can make an informed decision. After you approve or decline, your MCP client should resume automatically.

<Note>When an agent calls a tool with the **Ask** policy, only workspace owners can approve the call.</Note>
