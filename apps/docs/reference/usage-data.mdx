Self-hosted Coral sends one anonymous usage report for each day it runs. The reports show us how people use Coral, so we can make it better. Sharing is on by default. You can see each report before it goes, and you can turn sharing off.

## Which Coral sends a report

- Coral Desktop and shared servers send one report for each UTC day on which they run.
- Only official release builds send: the Coral Desktop downloads and the `ghcr.io/withcoral/coral` image. A build from source or a development build never sends. Its Usage data page shows the report and tells you why it does not send.
- Coral Cloud never sends a report.

Coral sends the report to `https://telemetry.withcoral.com/v1/report`. The `[outbound]` policy in your [configuration](/reference/configuration#outbound) still applies. When Coral cannot send a report, for example when it is offline, it keeps the report and sends it later.

## What a report holds

A report holds only dates, counts and values from fixed lists:

- **Install ID.** A random ID that Coral makes once for each deployment. It does not identify you, your organization or your computer.
- **Coral.** The version, the operating system and the processor type. Also the deployment type (desktop or server), the sign-in mode (off or required) and the database (SQLite or Postgres).
- **Milestones.** The date of the first successful run, the first saved function, and the first time a later task uses a saved function.
- **One day of counts.** Runs by result, and failed runs by failure type. Tool calls, approvals, saved functions saved and called, and tasks started. Runs by MCP client, from a fixed list of clients, with all other clients as "other". This release does not record the client yet, so it sends no clients.
- **Totals.** The number of workspaces, users, agents and saved functions. Providers by type (OpenAPI or MCP). Coral never sends their names. This release does not record which Coral recipe made a provider, so it counts those providers by type too. Accounts by connection type (OAuth or secret).

## What a report never holds

- Programs, tool arguments or tool results.
- Credentials, tokens or keys.
- The names that people give things, such as workspace, provider, function or agent names.
- Email addresses, user names, URLs or error messages.

We do not store your IP address or the request headers. We keep the reports. When you turn sharing off, Coral stops sending, but we keep the reports that you sent before.

## See the report

Open **Help and feedback**, then **Usage data**. Every member of the organization can read this page.

- **Today so far** shows the next report, word for word.
- **What Coral sent last** shows the last report and its UTC send time.

## Turn off sharing

### On the Usage data page

Only organization owners can change this setting. One setting applies to the full deployment, not to each workspace or user. Members can read the page but cannot change the setting.

1. Open **Help and feedback**, then **Usage data**.
2. Turn off **Share anonymous usage data**.

When sharing is off, Coral sends nothing. When you turn it on again, that day's counts start from that moment. Counts never include activity from while sharing was off. Milestones show the earliest date in the history Coral keeps, even if sharing was off then.

### With an environment variable

Each of these variables stops sending for the Coral process that reads it:

| Variable          | Stops sending when it is                   |
| ----------------- | ------------------------------------------ |
| `DO_NOT_TRACK`    | Set to a value other than empty, `0` or `false` |
| `CORAL_TELEMETRY` | `0` or `false`                                  |
| `CI`              | Set, to any value, even an empty one            |

Coral ignores spaces around a value and ignores letter case. Coral reads these variables only when it starts. Restart Coral after you change one.

Set the variable in the environment of each Coral server, or of Coral Desktop. While a variable applies, the Usage data page still shows the report. A banner names the variable that stops sending.

Coral makes no report for a day on which only such processes run. When you remove the variable, Coral does not send those days.
