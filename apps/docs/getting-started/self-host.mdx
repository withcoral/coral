You can run Coral as a shared server that you host yourself. You and your team then share workspaces, providers and tool policies. You can also share provider credentials with the members of a workspace.

Self-hosted Coral has two components:

- `coral`: the Docker image with the Coral server. It includes the runtime, the provider configuration, the policies, the authentication server and the MCP server.
- `coral-web`: the Coral UI, where you and your team manage Coral.

You can deploy Coral with [Docker Compose](/getting-started/self-host/docker-compose) or [Kubernetes](/getting-started/self-host/kubernetes).

## Before you start

- **An OIDC identity provider.** Self-hosted Coral uses your own identity provider (IdP) to authenticate users. Any OIDC-compatible IdP works, such as Okta, Google Workspace or WorkOS. Configure an application for Coral at your IdP.
- **A database.** Coral supports SQLite and Postgres. SQLite is the default. Choose the one that fits your setup.
- **TLS termination.** Coral requires TLS for user-facing connections, but Coral does not provide TLS itself. Use your preferred reverse proxy, such as nginx or Envoy. If you have none, use Caddy.
- **Public endpoints.** Coral uses three endpoints that your users' systems must be able to reach. `<coral-host>` is the placeholder for the root domain of your Coral deployment:
  - `<coral-host>`: the URL of the Coral UI (`coral-web`).
  - `auth.<coral-host>`: the auth endpoint. `coral-web` and the MCP server use it to authenticate users.
  - `mcp.<coral-host>`: the MCP server endpoint.

Make sure that you can point these names at your Coral deployment. The deployment guides have the details. Also make sure that you can create valid TLS certificates for these domains.

## Upgrade Coral

Coral updates its own database when a new version starts. You don't run a separate migration step.

To upgrade:

1. Read the [release notes](https://github.com/withcoral/coral/releases) for the versions between yours and the new one.
2. Back up Coral's state:
   - **SQLite.** Stop Coral, then copy the volume mounted at `/var/lib/coral`. It holds the database and the credentials key.
   - **Postgres.** Take a dump or a snapshot of the database. Keep the value of `CORAL_CREDENTIALS_KEY` with it.
3. Start the new `coral` and `coral-web` images. Upgrade both to the same version.

On Postgres, some upgrades cannot skip a version. If Coral does not start and says that the upgrade skips a version, start each version in between, in order. Then start the new one.

To return to an earlier version, restore the backup and start that version. An earlier version can start on a database that a later version updated, or refuse to. Do not use it as a way back.

The [Docker Compose](/getting-started/self-host/docker-compose#upgrade) and [Kubernetes](/getting-started/self-host/kubernetes#upgrade) guides have the commands.

## Upgrade from Coral 0.x

Coral 1.0 is a rewrite from the ground up. Your agents now write TypeScript programs that call your providers. In 0.x, they ran SQL queries over sources. You now manage Coral in the Coral UI, where 0.x used `coral` commands. Your agents now connect to the MCP server over HTTP, where 0.x used stdio.

So 1.0 is a breaking change. It starts from fresh state and doesn't convert what 0.x stored. Your 0.x setup stays as it is until you're ready to switch.

The Coral 1.0 runtime stops when it starts on a configuration folder or a database that an earlier version wrote. It reports an error such as:

```text
pre-v1 Coral state detected at '<configuration folder>'; move or remove it before starting this version of Coral
pre-v1 Coral database state detected; move or remove it, or configure a fresh database before starting this version of Coral
```

Coral never deletes, converts or archives old state. Don't start a Coral 1.0 container on a 0.x volume, because the container overwrites `config.toml` there.

To start Coral 1.0:

1. Stop the old Coral. Copy its configuration folder, or its volume, and keep the copy for as long as you need it.
2. Give Coral 1.0 fresh state. Set `CORAL_CONFIG_DIR` to an empty folder or, in containers, mount a new volume. With Postgres, point Coral at an empty database.
3. Write a new configuration from the [configuration reference](/reference/configuration), or follow one of the guides below. Coral 1.0 rejects a 0.x configuration file.
4. Start Coral, then add your providers and connect your accounts again.
5. Point your agents' MCP clients at the new MCP endpoint.

To go back, stop Coral 1.0 and start the old version on the copy you kept.
