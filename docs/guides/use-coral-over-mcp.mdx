Coral ships with a built-in MCP server that presents Coral to agents as a compact capability interface. Agents discover generated exports with `search` and `describe`, then run work through Code Mode with `exec` and `wait`.

<Note>
Before setting up a client, make sure you have [connected at least one source](/getting-started/quickstart).

</Note>

## What MCP clients get

| Type | Name       | Description                                                   |
| ---- | ---------- | ------------------------------------------------------------- |
| Tool | `search`   | Search current workspace exports and generated capabilities   |
| Tool | `describe` | Describe a typed ref, capability id, or unambiguous alias     |
| Tool | `exec`     | Run Code Mode, waiting briefly for fast completion            |
| Tool | `wait`     | Wait for new Code Mode output, or terminate a running run     |
| Tool | `feedback` | Blocked-agent feedback tool                                  |

Clients see generated TypeScript refs, SQL refs, capability ids, source identity, effect-profile summaries, and diagnostics. The MCP tool list is intentionally stable: adding or removing sources changes `search` and `describe` results, not the MCP tools themselves.
Successful MCP tool calls return structured JSON in `structuredContent`; Coral does not duplicate successful JSON payloads as fenced markdown text.

Use `coral --runtime-exposure typescript mcp-stdio` to expose only TypeScript invocation bindings, or `coral --runtime-exposure sql mcp-stdio` to expose only SQL projection bindings. The default is `both`. TypeScript-only exposure hides SQL refs and `coral.sql.query(...)`; SQL-only exposure hides generated TypeScript methods while leaving discovery and SQL Code Mode available.

### `search`

Use `search` to find generated exports. Arguments are optional unless you want to narrow the result set:

- `query`: text, typed ref, capability id, generated tool path, TypeScript path, or SQL ref
- `source_key`, `display_name`: source filters. `source_key` is the human-facing source handle (e.g. `"slack"`, `"github"`) and is the selector to reach for. To browse one source's whole surface, pass `source_key` with an empty `query`.
- `kind`: `typescript`, `sql_table`, or `sql_function` when SQL exposure is enabled; TypeScript-only exposure narrows this to `typescript`
- `capability_kind`: `query`, `mutation`, or `action`
- `effect`: `read`, `write`, `delete`, or `unknown`
- `limit`, `offset`: pagination

Unknown arguments are rejected rather than silently ignored, so a typo like `source` or `provider` errors instead of degrading to an unfiltered search.

Exact typed-ref, capability-id, generated tool path, TypeScript-path, and SQL-ref matches rank ahead of text matches. Otherwise ranking is recall-first and provider-agnostic: any capability whose title, description, or **input-parameter names and descriptions** overlap the query is returned (it is never gated away before ranking), with common terms down-weighted by inverse document frequency. Search results are structured for agents: each item includes a preferred `ref`, generated Code Mode `call` path when TypeScript is visible, SQL `sql` ref when SQL is visible, `source_key`, `capability_kind`, `effect` or `effects`, `title`, `description`, a page-relative `score`, an absolute `raw_score` for cross-page comparison, `matched_terms`, `matched_fields`, `rank_reason`, and `input_schema_available`. Default values such as `support: "generated"`, `deprecated: false`, and zero diagnostics are omitted. Top-level `pagination` reports `limit`, `offset`, `total`, and `next_offset`; top-level `diagnostics` reports workspace discovery problems, such as installed sources whose generated artifacts need to be regenerated.

### `describe`

Use `describe` before invoking anything. Pass `reference` as a generated tool path such as `tools.github.rest.issues.list`, a typed ref such as `typescript:github.rest.issues.list`, a SQL ref such as `sql_table:github_rest.issues` or `sql_function:github_rest.search`, a capability id, or an unambiguous alias.

If an untyped reference is ambiguous, `describe` returns grouped candidates instead of guessing. Retry with a typed ref from the candidate list. If a source is installed but stale, not-found responses include top-level `diagnostics` instead of silently looking like the source does not exist.

For found capabilities, MCP `describe` defaults to a compact invocation contract: preferred `ref`, generated `call` path when TypeScript is visible, SQL `sql` ref when SQL is visible, `source_key`, `capability_kind`, `effect` or `effects`, title/description, `input_schema`, `output_schema`, structured examples, SQL bindings, and diagnostics. It does not encode argument schemas as prose strings. Use `describe` with `view: "detailed"` when you need full provider artifacts, credential requirements, or generated export provenance. Generated calls return Coral's wrapper object; read provider data from `response.value` only after `response.ok` is true.

### `exec` and `wait`

Use Code Mode for execution. `exec` accepts JavaScript source in the `source` argument and returns `{ run, result, events }`. `run.status` is the execution status. `result` is either `null` or an object with `status`, `format`, `truncated`, `preview`, and optional `artifact`/`truncation` metadata. `events.items` contains incremental stdout/content events, and `events.next_after_event_id` is the cursor for `wait`. Call `wait` while `events.has_more` is true. To stop a running run, call `wait` with `terminate: true`.

Code Mode runs in Coral's V8 isolate. Supported globals are generated `tools.*`, Coral helpers under `coral.*`, standard JavaScript, `console.*`, and the documented helpers in the `exec` description.

Code Mode exposes Coral host helpers and generated provider methods:

```javascript
await coral.search({ query: "github issues" });
await coral.describe({ reference: "tools.github.rest.issues.list", view: "compact" });
await coral.sql.query("select * from github_rest.issues limit 5");
const response = await tools.github.rest.issues.list(
  { owner: "withcoral", repo: "coral" },
  { allowErrorResult: true }
);
if (!response.ok) return response;
const { value } = response;
return value;
```

When TypeScript exposure is disabled, generated TypeScript methods fail before capability invocation. When SQL exposure is disabled, `coral.sql.query(...)` and SQL refs are hidden.

Generated TypeScript methods call `CapabilityService.Invoke` inside Coral. They do not call providers directly, do not receive credentials, and do not bypass source-level provider auth. Query, mutation, and action capabilities are callable by default. For dynamic workflows, use `call` from `search` or `describe` and call the generated method under `tools.*` inside Code Mode. Generated methods reject on provider or transport failure by default; the rejection is catchable with JavaScript `try`/`catch`, and an uncaught rejection fails the run. Successful calls return `{ ok, complete, partial, errors, source_status, value, error, envelope }`. REST calls expose transport details such as `envelope.provider.status` and lowercase response headers at `envelope.provider.headers`. MCP calls expose `structuredContent` as `value`; when an upstream MCP server returns no `structuredContent` but does return one text block containing exact JSON or one `json` fenced code block, Coral parses that JSON into `value` while leaving the raw MCP content in `envelope`. To deliberately collect a raw error envelope, pass a second options object: `await tools.github.rest.issues.list(args, { allowErrorResult: true })`; raw error results are visibly incomplete through `complete`, `partial`, `errors`, and `source_status`. Provider error details are bounded structured diagnostics when available, such as HTTP status/body previews, MCP protocol errors, or MCP `isError` tool results.

Code Mode enforces explicit default nested-call budgets. A run fails at the top level when it exceeds `max_nested_tool_calls=100` or `max_parallel_tool_calls=100`; total nested invocations are counted by `max_nested_tool_calls`. Budget errors include the limit name, configured value, observed count, and invocation path. Direct result previews default to `max_output_tokens=10000` unless overridden with the first-line `// @exec` pragma; oversized direct results still complete the run and surface truncation on `result.truncated`, with `result.preview`, `result.truncation`, and `result.artifact` when Coral can spill the complete JSON result to disk. Spilled direct results are capped by `max_output_result_spill_bytes=1048576`; larger results still return the preview plus `truncation.max_spill_bytes`, but no full-output path. Verbose `console.*` diagnostics are bounded separately as content events; when Coral truncates, drops, or spills console text, `events.items` includes an `output_shaping` event with the limit name, observed/dropped counts, and `full_output_path` when available. Spilled console text is capped by `max_output_text_spill_bytes=1048576`; after that, diagnostics are dropped with metadata instead of failing the run or growing the spill file indefinitely.

When a SQL binding exists, run SQL from Code Mode through `coral.sql.query(...)`. Coral does not expose direct SQL MCP tools.

## Client setup

Coral uses stdio transport. If a client supports a command-based install flow, point it at `coral mcp-stdio`.

  <Tabs>
    <Tab title="macOS / Linux">
    ```shellscript
    npx add-mcp -n coral -g "$(which coral) mcp-stdio"
    ```
    </Tab>

  Add to `~/.config/opencode/opencode.json` for global scope, or `opencode.json` in your project root for project scope:

  ```json
  {
    "$schema": "https://opencode.ai/config.json",
    "mcp": {
      "coral": {
        "type": "local",
        "command": ["coral", "mcp-stdio"],
        "enabled": true
      }
    }
  }
  ```

  OpenCode merges global and project config, with project config taking precedence over global config.

## Verify the connection

Once your client is connected, ask the agent to search available capabilities or run a small Code Mode SQL query. Examples:

> "Search Coral for GitHub issue capabilities."

> "Run `select 1` through Coral Code Mode."

The agent should call `search` to find generated call paths and typed refs, `describe` to inspect JSON schemas, and `exec` to run Code Mode. Call `wait` while `events.has_more` is true, using `events.next_after_event_id`. SQL runs inside Code Mode with `coral.sql.query(...)`.

## Troubleshooting

- **`coral` not found:** Make sure `coral` is on your `PATH`, or use the full path from `which coral` on macOS or Linux or `(Get-Command coral).Source` in PowerShell.
- **No tables visible:** Confirm SQL exposure is active, then run `search`/`describe` to see whether installed sources project `sql_table:*` or `sql_function:*` refs. Some sources expose generated TypeScript capabilities without SQL projections.
- **No capabilities visible for an installed source:** Inspect `diagnostics` from `search` or `describe`. `SOURCE_ARTIFACTS_UNAVAILABLE` means the source must be re-added so Coral can regenerate its capability artifacts.
