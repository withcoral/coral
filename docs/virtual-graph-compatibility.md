# Virtual Graph Compatibility Matrix

This matrix tracks production support. It is intentionally stricter than a PoC:
unsupported behavior should be rejected clearly instead of guessed.

## Declaration

| Feature | Status | Notes |
| --- | --- | --- |
| v1 YAML declarations | Supported foundation | Nodes, relationships, table refs, keys, properties |
| Duplicate label rejection | Supported foundation | One node table per graph label |
| Duplicate relationship mapping rejection | Supported foundation | Relationship mappings must have a unique `type + from label + to label` signature |
| Endpoint label validation | Supported foundation | Relationship endpoints must reference declared node labels |
| Catalog validation | Supported foundation | Checks mapped tables, columns, and required-filter constraints during explicit validation and query execution/explain |
| Multiple mappings per relationship type | Supported foundation | The validator selects the mapping by endpoint labels and direction; ambiguous undirected inverse mappings are rejected |

## Shared Graph IR

| Feature | Status | Notes |
| --- | --- | --- |
| Node scans | Supported foundation | One table per label |
| Directed relationship traversals | Supported foundation | Forward and reverse traversal lower to joins |
| Relationship type overloads | Supported foundation | A relationship type can map to multiple edge tables when endpoint labels disambiguate the pattern |
| Connected multi-hop paths | Supported foundation | Linear and closed connected patterns lower to deterministic joins |
| Disconnected mandatory patterns | Supported foundation | Disconnected mandatory node/path components lower to explicit SQL `CROSS JOIN`; `OPTIONAL MATCH` may connect already-bound components through a single nullable chain or start a disconnected nullable component by cross-joining an anchor inside that component |
| Property projections | Supported foundation | Node keys and exposed properties |
| Property predicates | Supported foundation | Literal and property-to-property comparisons with boolean expression trees |
| Numeric literals | Supported foundation | Integer and finite floating-point literals, including negated values |
| `COUNT(*)` | Supported foundation | Standalone or grouped by projected properties |
| `COUNT(property)` | Supported foundation | Counts non-null mapped property values and supported scalar expression targets such as `count(coalesce(n.tier, 'unknown'))` or `count(n.tier IS NULL)`; optional `DISTINCT` is supported; endpoint forms such as `count(endNode(r).name)` over optional relationships are null-gated by relationship presence |
| `COUNT(node)` | Supported foundation | Counts node key occurrences; `COUNT(DISTINCT node)` counts distinct declared node keys; endpoint forms such as `count(endNode(r))` over optional relationships count only matched relationship rows |
| `COUNT(relationship)` | Supported foundation | Counts relationship rows for keyed or keyless mappings; `COUNT(DISTINCT relationship)` requires a declared relationship key |
| Collection aggregate functions | Supported foundation | `COLLECT(property)`, `COLLECT(DISTINCT property)`, `COLLECT(node)`, `COLLECT(DISTINCT node)`, keyed relationship or endpoint variants, and supported scalar expression targets such as `collect(coalesce(n.tier, 'unknown'))` or `collect(n.risk > 0.8)` lower to null-filtered DataFusion `ARRAY_AGG`; graph-variable collection returns mapped stable keys rather than materialized graph objects |
| Numeric aggregate functions | Supported foundation | `SUM`, `AVG`, `MIN`, and `MAX` over mapped graph properties, optional relationship endpoint properties such as `sum(endNode(r).risk)`, and supported scalar expression targets such as `sum(n.risk + 1)` |
| Grouped aggregate projections | Supported foundation | Property projections become SQL `GROUP BY` keys |
| Distinct projections | Supported foundation | `SELECT DISTINCT` over projected rows |
| Literal projections | Supported foundation | String, integer, finite float, boolean, null, scalar parameter literals, and non-empty homogeneous literal/list-parameter values can be projected |
| Identity projections | Supported foundation | `id(node)`, `id(keyedRelationship)`, `elementId(node)`, `elementId(keyedRelationship)`, and `type(relationship)` lower through mapped keys and fixed relationship types; `elementId` casts mapped keys to strings; optional `type(relationship)` and optional `startNode(relationship)` / `endNode(relationship)` identity expressions return null when the relationship is unmatched |
| Node label projections | Supported foundation | `labels(node)` lowers to a one-element DataFusion list containing the statically mapped node label and preserves null for unmatched optional nodes and optional relationship endpoint expressions such as `labels(endNode(r))` |
| Property key projections | Supported foundation | `keys(node)` and `keys(relationship)` lower to a deterministic list of declared graph property names and preserve null for unmatched optional bindings and optional relationship endpoint expressions such as `keys(startNode(r))` |
| Identity predicates | Supported foundation | `WHERE id(...)` compares mapped keys; `WHERE elementId(...)` compares string-cast mapped keys and rejects keyless relationships; `WHERE type(r)` is folded from the fixed relationship type |
| Ordering, skip, and limit | Supported foundation | Property order keys, identity order keys, boolean predicate scalar order keys, direct projected and hidden aggregate expressions, projection aliases including aggregate aliases, row offset, and row limit |
| Execute/explain wrappers | Supported foundation | Preserves translated SQL and diagnostics |
| Declaration-aware plan validation | Supported foundation | Graph-aware Cypher and GraphQL compile/execute/explain paths resolve variables/properties and reject unsupported plan shapes before SQL rendering |
| Optional matches | Supported foundation | Anchored optional relationship scopes lower to `LEFT JOIN`; single-hop and connected multi-hop optional chains preserve unmatched rows with nullable optional bindings, including chains between two already-bound endpoints. Directed and undirected optional-local predicates and inline property maps lower into the nullable join scope. In branch-expanded plans, optional-local predicates normalize missing node or relationship properties to branch-local `NULL` before validation. Later mandatory `MATCH` clauses may continue from optional-introduced node bindings, lowering as inner joins that naturally drop rows where the optional binding was unmatched. Later global `WHERE` predicates over still-optional bindings lower as ordinary row filters, while `OPTIONAL MATCH ... WHERE` predicates stay inside the nullable join scope to preserve unmatched rows. |
| Bounded variable-length path expansion | Supported foundation | Frontends may lower finite bounded mandatory path ranges into ordinary fixed-hop branch plans. Zero-hop branches are represented as same-node key identity predicates for same-label endpoints or as statically false branches for incompatible labels. Declaration-aware Cypher expansion prunes impossible exact-hop alternatives for cross-label endpoints, keeps only unambiguous label paths, and compiles all-pruned schema ranges as empty result plans. Unbounded recursive/path expansion remains deferred. |
| Path values | Partial | Fixed and bounded path bindings can project ordered mapped-key arrays through `nodes(path)` and `relationships(path)`, and can lower static indexes, slices, `head(...)`, `last(...)`, `tail(...)`, and `reverse(...)` over those path element lists to mapped-key scalar/list expressions; full graph-object path values remain deferred |

## Frontends

| Feature | Status | Notes |
| --- | --- | --- |
| Cypher parser | Supported foundation | `decypher` AST frontend compiles to shared IR, not directly to SQL |
| Single `MATCH ... RETURN` | Supported foundation | One non-optional MATCH clause with one or more mandatory pattern parts |
| Comma-separated `MATCH` patterns | Supported foundation | Connected parts lower to joins; disconnected mandatory parts lower to explicit SQL `CROSS JOIN` |
| Labeled node patterns | Supported foundation | Named node variables are supported; declaration-aware Cypher compile/execute/explain can infer an omitted label for a fresh named or anonymous endpoint when an exact typed relationship pattern, including exact fixed-length and zero-hop ranges/quantifiers, or an untyped exact single-hop relationship pattern, and the graph declaration identify one unique endpoint label. Declaration-aware standalone unlabeled node scans such as `MATCH (n)` and anonymous `MATCH ()`, plus row-preserving label alternatives such as `(owner:Person|Team)-[r:OWNS]->(...)`, expand over declared mappings through capped `UNION ALL` branch planning; node or relationship property projections, scalar projection expressions, hidden `ORDER BY` columns, aggregate source columns, aggregate scalar expression targets, predicates, and scoped `EXISTS` / existence-style `COUNT` predicate bodies that reference properties missing from a branch are rendered with typed `NULL` branch values. Missing-property predicate normalization preserves SQL/Cypher null and unknown semantics for comparison trees, including `IS NULL`, `IS NOT NULL`, and negated comparisons, while scalar wrappers such as `coalesce(n.tier, 'unknown')` or `coalesce(r.since, 'unknown')` keep their normal semantics after branch-local null rewriting. Ambiguous overloads are rejected with guidance to add an explicit label, and declaration-free compilation still requires first-bound named variables and anonymous nodes to carry a label. Anonymous node patterns are also supported when they resolve to exactly one positive static or compile-time dynamic label; dynamic atoms such as `:$($label)` are accepted when the inner expression is a string literal, scalar string parameter, non-empty literal string list, folded static string-list expression, statically selected list-valued `CASE`, or non-empty list string parameter that can be expanded into branches. Static exclusions such as `:Service&!Team`, grouped exclusions such as `:Service&!(Team|Legacy)`, and compile-time dynamic exclusions are accepted when the selected Coral mapping satisfies the full label expression. Bounded relationship-range pruning resolves compile-time dynamic endpoint labels before checking declaration topology. Row-dependent dynamic labels, empty or non-string list-valued dynamic labels, multiple required labels, and contradictory label expressions are rejected. |
| Typed directed relationships | Supported foundation | Requires one positive static or compile-time dynamic relationship type per expanded branch, or declaration-aware inference for an untyped exact single-hop relationship whose endpoint labels identify one unique relationship type. Dynamic atoms such as `:$($type)` are accepted when the inner expression is a string literal, scalar string parameter, non-empty literal string list, folded static string-list expression, statically selected list-valued `CASE`, or non-empty list string parameter that can be expanded into branches. Static exclusions such as `:OWNS&!DEPENDS_ON`, grouped exclusions such as `:OWNS&!(DEPENDS_ON|ALERTS)`, and compile-time dynamic exclusions are accepted when the selected Coral relationship mapping satisfies the full type expression. Bounded relationship-range pruning resolves compile-time dynamic relationship types before checking declaration topology. Row-dependent dynamic types, empty or non-string list-valued dynamic types, multiple required types, contradictions, ambiguous untyped mappings, and untyped relationship ranges are rejected. Exact-one relationship ranges/quantifiers such as `*1`, `*1..1`, `{1}`, and `{1,1}` are accepted as single-hop syntax compatibility |
| Static and compile-time dynamic pattern label/type alternatives | Supported foundation | Row-preserving single-query patterns such as `(n:Person|Team)`, `(n:Team|$($label))`, `(n:$(['Person', 'Team']))`, `(n:$(split('Person,Team', ',')))`, `(n:$(CASE WHEN true THEN ['Person'] ELSE ['Team'] END))`, `(n:$($labels))` for non-empty list string parameters, declaration-aware standalone `MATCH (n)`, `-[r:OWNS|DEPENDS_ON]->`, `-[r:OWNS|$($type)]->`, `-[r:$(['OWNS', 'DEPENDS_ON'])]->`, `-[r:$(split('OWNS,DEPENDS_ON', ','))]->`, `-[r:$(CASE WHEN true THEN ['OWNS'] ELSE ['DEPENDS_ON'] END)]->`, and `-[r:$($types)]->` for non-empty list string parameters expand to `UNION ALL` branches with a capped branch count. Compile-time dynamic alternative atoms are resolved from string literals, scalar string parameters, literal string lists, folded static string-list expressions, statically selected list-valued `CASE`, or scalar string-list parameters before branch expansion and deduplication; row-dependent dynamic expressions, non-foldable `CASE WHEN` predicates, empty label/type lists, and non-string list members are rejected. Final `RETURN DISTINCT`, standalone or grouped `count(*)`, grouped `count(property)`, `count(variable)`, `count(DISTINCT variable)`, `collect(property)`, `collect(variable)`, `collect(DISTINCT variable)`, optional relationship endpoint aggregates such as `count(endNode(r))`, `collect(endNode(r))`, and `sum(endNode(r).risk)`, numeric/statistical property aggregates such as `sum(n.score)` or `avg(n.score)`, aggregate scalar expression targets such as `collect(coalesce(n.tier, 'unknown'))`, `collect(n.score > 0.8)`, and `sum(n.score + 1)`, row-preserving scalar count-subquery projections, projected-expression or alias `ORDER BY`, row-preserving hidden `ORDER BY` expressions, explicit `NULLS FIRST`/`NULLS LAST` order placement, `SKIP`, and `LIMIT` are applied after or within the expanded union as appropriate. Static-alternative graph-variable collections use internal label/type-qualified graph identities so keys from different mapped tables do not collide, while relationship endpoint collections use the endpoint's mapped key and filter unmatched optional rows. Row-preserving alternatives can be flattened inside explicit top-level `UNION ALL`. Queries with correlated subqueries inside aggregate expression targets, hidden ordering for aggregate or `RETURN DISTINCT` alternatives, `WITH DISTINCT`, `WITH ORDER BY`/`SKIP`/`LIMIT`, explicit top-level `UNION` distinct, or branch-level alternative modifiers inside explicit `UNION ALL` remain rejected until Coral has broader staged outer-query planning. |
| Undirected relationships | Supported foundation | Lowers to orientation-aware joins; same-label relationships use disjunctive endpoint conditions; inverse overloaded mappings that both match are rejected as ambiguous. `startNode(r)` and `endNode(r)` over cross-label undirected relationships use the single matching graph declaration mapping to recover original edge orientation. Same-label undirected endpoint property reads, identity scalars such as `id(startNode(r))` and `elementId(endNode(r))`, metadata lists such as `labels(startNode(r))` and `keys(endNode(r))`, endpoint graph-object returns such as `RETURN startNode(r) AS source`, and endpoint identity aggregate targets such as `count(DISTINCT startNode(r))` lower to searched `CASE` expressions over the mapped relationship `from`/`to` key columns, so both matched row orientations report the declared edge source and target. Ambiguous overloaded undirected endpoint functions remain deferred. |
| Multi-hop relationship chains | Supported foundation | Forward, reverse, and mixed chains compile through the shared graph IR |
| Parenthesized path patterns | Supported foundation | Transparent path parentheses such as `MATCH ((a)-[:OWNS]->(b))`, named variants such as `MATCH p = ((a)-[:OWNS]->(b))`, exact-one grouped quantifiers such as `((a)-[:OWNS]->(b)){1}` / `{1,1}`, static label/type alternatives, bounded ranges, and anchored `OPTIONAL MATCH` forms lower through the same path-pattern compiler. Non-exact quantified parenthesized path patterns remain rejected until Coral has grouped path-pattern repetition planning. |
| Multiple `MATCH` clauses | Supported foundation | Transparent multi-part read clauses compile into one connected graph plan |
| `WHERE` property comparisons | Supported foundation | String, integer, float, boolean, null literal, property-to-property comparisons, relationship-property comparisons, arithmetic scalar predicates, and scalar-expression RHS comparisons |
| `WHERE id(...)` predicates | Supported foundation | Node ids and keyed relationship ids lower to mapped key comparisons and `IN` predicates |
| `WHERE type(r)` predicates | Supported foundation | Folded to boolean predicates because each relationship pattern has one static type; equality, inequality, `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, and regex matching are supported |
| `WHERE node:Label` / `relationship:TYPE` predicates | Supported foundation | Static label/type expressions fold against the mapped node label or relationship type, including grouped conjunction/disjunction/negation. Dynamic predicate atoms such as `node:$($label)`, `node:$(['Label', 'Other'])`, `node:$(split('Label,Other', ','))`, `node:$(CASE WHEN true THEN ['Label'] ELSE ['Other'] END)`, `node:$($labels)`, `relationship:$($type)`, `relationship:$(['TYPE', 'OTHER'])`, `relationship:$(split('TYPE,OTHER', ','))`, `relationship:$(CASE WHEN true THEN ['TYPE'] ELSE ['OTHER'] END)`, and `relationship:$($types)` are accepted when the inner expression is a string literal, scalar string parameter, non-empty literal string list, folded static string-list expression, statically selected list-valued `CASE`, or non-empty string-list parameter and are folded against the mapped label/type. Runtime graph-property dynamic labels, non-foldable `CASE WHEN` predicates, empty label/type lists, and non-string list members remain rejected. |
| Chained comparisons | Supported foundation | Normalized to conjunctions, e.g. `10 <= n.score < 20` |
| Literal-left comparisons | Supported foundation | Operators are inverted around the property operand where possible |
| Literal-only predicates | Supported foundation | Non-null literal comparisons, including ordered numeric and string comparisons, and literal `IN` membership fold to boolean predicates; null-producing unknown cases are rejected instead of guessed |
| `WHERE` boolean logic | Supported foundation | `AND`, `OR`, `XOR`, `NOT`, and parentheses lower to SQL boolean predicates; `XOR` is rendered as a null-preserving boolean rewrite instead of relying on target-specific SQL syntax |
| `WHERE ... IN [...]` | Supported foundation | Literal scalar lists, including numeric and null members, lower to SQL `IN`; empty lists lower to `FALSE`. Static folded list expressions such as `property IN (['prod'] + $tiers)`, `property IN keys(optionalNode)`, `property IN (keys(optionalNode) + ['extra'])`, `property IN [k IN keys(node) WHERE k != 'deprecated' | k]`, `property IN coalesce(keys(optionalNode), ['fallback'])`, `property IN [k IN coalesce(keys(optionalNode), ['fallback']) | k]`, `property IN coalesce(keys(optionalNode), ['fallback'])[0..1]`, `property IN CASE WHEN optionalNode IS NULL THEN ['fallback'] ELSE keys(optionalNode) END`, `property IN [k IN CASE WHEN optionalNode IS NULL THEN ['fallback'] ELSE keys(optionalNode) END | k]`, and `property IN (CASE WHEN optionalNode IS NULL THEN ['fallback'] ELSE keys(optionalNode) END)[0..1]` are supported as RHS values; optional graph bindings preserve unmatched rows as `NULL` through presence gating or branch-local fallback logic. |
| `WHERE '<Label>' IN labels(node)` | Supported foundation | String-literal and scalar string parameter membership predicates fold against the statically mapped node label; optional relationship endpoint forms preserve optional-match null semantics |
| `WHERE '<key>' IN keys(variable)` | Supported foundation | String-literal and scalar string parameter membership predicates lower against declared graph property metadata; optional relationship endpoint forms preserve optional-match null semantics |
| `WHERE labels(node) = [...]` / `keys(variable) = [...]` / `tail(list) = [...]` | Supported foundation | Declaration-aware equality, inequality, and lexicographic ordered comparisons against literal lists, list parameters, `tail(...)`, or other static list expressions fold from static node-label and declared-property metadata. Reversed operands such as `['Service'] = labels(node)`, `[] = tail(labels(node))`, and `['Team'] > labels(node)` are supported. Ordered comparisons require compatible string or numeric folded-list element families; boolean and cross-family ordered lists are rejected. Optional node and relationship endpoint forms preserve null semantics through the same presence-gated scalar IR used by metadata projections, and null element comparisons fold to Cypher unknown. |
| `all` / `any` / `none` / `single` collection predicates | Supported foundation | Static collection predicates such as `all(k IN keys(node) WHERE k != 'deprecated')`, `any(k IN tail(keys(node)) WHERE k = 'tier')`, `any(k IN keys(node) WHERE k > 'team')`, `none(label IN labels(node) WHERE label = 'Team')`, `any(k IN coalesce(keys(optionalNode), ['fallback']) WHERE k = 'fallback')`, `any(k IN coalesce(keys(optionalNode), ['fallback'])[0..1] WHERE k = 'fallback')`, `any(k IN CASE WHEN optionalNode IS NULL THEN ['fallback'] ELSE keys(optionalNode) END WHERE k = 'team')`, `any(k IN (CASE WHEN optionalNode IS NULL THEN ['fallback'] ELSE keys(optionalNode) END)[0..1] WHERE k = 'team')`, and predicates over literal or list-parameter collections fold at compile time or lower as branch-local scalar predicates for static-list `CASE` / `coalesce(...)` collections. Supported item predicates include the filter variable, literals, scalar parameters, equality/inequality, ordered numeric and string comparisons, string predicates (`STARTS WITH`, `ENDS WITH`, `CONTAINS`, and regex), `IN` against static lists, `IS NULL`, and `AND`/`OR`/`XOR`/`NOT`. Optional graph metadata collections preserve null semantics with presence-gated boolean scalars or branch-local fallback logic, and null-sensitive item outcomes preserve Cypher unknown semantics. Dynamic collections remain rejected. |
| Static list indexes | Supported foundation | Positive and negative integer indexes over folded static lists, including `labels(...)`, declaration-aware `keys(...)`, `tail(...)`, `reverse(...)`, static list concatenation, and list-valued static `CASE` / `coalesce(...)`, fold at compile time or lower branch-locally in projections, predicates, searched `CASE WHEN`, and `ORDER BY`; out-of-range indexes fold to `NULL`. Optional node and endpoint forms preserve null semantics through presence-gated scalar IR. Dynamic list indexing remains rejected. |
| Static list slices | Supported foundation | Start-inclusive/end-exclusive slices over folded static lists, including `labels(...)`, declaration-aware `keys(...)`, `tail(...)`, `reverse(...)`, and static list concatenation, fold at compile time in projections, equality predicates, `size(...)`, `isEmpty(...)`, nested indexes, `UNWIND`, and `ORDER BY`. Optional node and endpoint forms preserve null semantics through presence-gated list scalar IR. Empty projected slices are supported by carrying a typed folded-list expression through the IR and rendering typed empty arrays in DataFusion SQL. Branch-local slices over list-valued static `CASE` / `coalesce(...)` currently compose in projections, `ORDER BY`, equality/inequality/ordered comparisons, `IN` right-hand sides, static collection predicates, `head(...)`, `last(...)`, `size(...)`, `isEmpty(...)`, nested indexes, list-comprehension scalar projections/order keys, list-comprehension equality/ordered comparison or `IN` predicates, and static `UNWIND`. |
| `head(list)` / `last(list)` / `tail(list)` | Supported foundation | Literal lists, list parameters, and static `labels(...)` / declaration-aware `keys(...)` metadata lists fold at compile time in projections, predicates, searched `CASE WHEN`, and `ORDER BY`; empty matched lists fold to `NULL` for `head(...)` / `last(...)`, while optional node and endpoint metadata preserves unmatched rows as `NULL`. `tail(...)` returns typed folded lists, including empty tails, and composes with `head(...)`, `last(...)`, `size(...)`, and `isEmpty(...)` when the input list has a known non-null element type. Ambiguous empty, all-null, or mixed-type list-valued `tail(...)` results are rejected. Dynamic list values remain rejected. |
| Static list `reverse(list)` | Supported foundation | List-valued `reverse(...)` folds literal lists, list parameters, `tail(...)`, static `labels(...)`, declaration-aware `keys(...)`, and static list concatenation at compile time. Folded reverse composes with projection, `ORDER BY`, `head(...)`, `last(...)`, `tail(...)`, `size(...)`, `isEmpty(...)`, exact list equality/inequality, static collection predicates, and optional graph metadata presence gates. String-valued `reverse(scalar)` still lowers as a normal scalar string function. Ambiguous empty, all-null, or mixed-type list-valued results are rejected. |
| Static list concatenation | Supported foundation | `+` concatenates foldable static lists from literal lists, list parameters, `tail(...)`, `labels(...)`, and declaration-aware `keys(...)`; it also supports Cypher-compatible `list + element` and `element + list` when the element is a scalar literal or scalar parameter. Concatenated lists compose with projection, `ORDER BY`, `UNWIND`, `head(...)`, `last(...)`, `tail(...)`, `size(...)`, `isEmpty(...)`, exact list equality/inequality, static `all`/`any`/`none`/`single`, static list comprehensions, and parenthesized `IN` RHS expressions. Nullable metadata lists on the right-hand side of `IN` preserve optional-match nulls through presence gating. Mixed element types, dynamic operands, projected all-null/empty unknown element types, and lists from different optional bindings are rejected. |
| Static list `coalesce(...)` | Supported foundation | List-valued `coalesce(...)` folds or lowers through the static-list scalar path when every non-null argument is a static list with a compatible element type. Literal lists, list parameters, static `split(...)` / `range(...)`, `tail(...)`, `reverse(...)`, static list concatenation, static list casts, `labels(...)`, and declaration-aware `keys(...)` are accepted in projections, `ORDER BY`, `IN` right-hand sides, static collection predicates, and indexed or sliced scalar forms such as `coalesce(keys(optionalNode), ['fallback'])[0]`, `coalesce(keys(optionalNode), ['fallback'])[0..1]`, and `(coalesce(keys(optionalNode), ['fallback'])[0..1])[0]`; optional metadata lists preserve unmatched rows through presence-gated list expressions, enabling fallbacks such as `coalesce(keys(optionalNode), [])`. `property IN coalesce(keys(optionalNode), ['fallback'])`, `property IN coalesce(keys(optionalNode), ['fallback'])[0..1]`, `any(k IN coalesce(keys(optionalNode), ['fallback']) WHERE k = 'fallback')`, and `any(k IN coalesce(keys(optionalNode), ['fallback'])[0..1] WHERE k = 'fallback')` lower as branch-local membership/collection predicates so an unmatched optional list falls through while a matched list still preserves null semantics. `head(coalesce(...))`, `last(coalesce(...))`, `size(coalesce(...))`, `isEmpty(coalesce(...))`, scalar indexes, and projection/ordering/comparison/endpoint/sizing/emptiness over sliced static-list branches lower by coalescing or selecting each branch's folded scalar/list value, so all-empty branches such as `size(coalesce([], []))` are valid without dynamic array-length SQL. Mixed scalar/list arguments, projected all-null or unknown empty element types, dynamic list columns, and lists from incompatible optional bindings remain rejected. |
| Static list `CASE` results | Supported foundation | Searched and generic `CASE` expressions may return static lists when every non-null `THEN` / `ELSE` branch is a compatible static-list expression. Literal lists, list parameters, static `split(...)` / `range(...)`, `tail(...)`, `reverse(...)`, static list concatenation, static list casts, static list comprehensions, `labels(...)`, declaration-aware `keys(...)`, and list-valued `coalesce(...)` branches are accepted in projections, `ORDER BY`, `IN` right-hand sides, static collection predicates, and indexed or sliced scalar forms such as `(CASE WHEN n IS NULL THEN ['fallback'] ELSE keys(n) END)[0]`, `(CASE WHEN n IS NULL THEN ['fallback'] ELSE keys(n) END)[0..1]`, and `((CASE WHEN n IS NULL THEN ['fallback'] ELSE keys(n) END)[0..1])[0]`. Empty-list branches are typed from another branch, optional metadata branches preserve unmatched rows through presence-gated list expressions, and scalar/list mixes, mixed element types, all-empty/all-null projected list results, and dynamic list columns remain rejected. `property IN CASE ... END`, `property IN (CASE ... END)[0..1]`, `any(k IN CASE ... END WHERE ...)`, and `any(k IN (CASE ... END)[0..1] WHERE ...)` lower to scalar boolean `CASE` branches over each folded list result, so all-empty/all-null branches can still participate in predicate position without rendering an untyped list. `head(CASE ... END)`, `last(CASE ... END)`, `size(CASE ... END)`, `isEmpty(CASE ... END)`, scalar indexes, and projection/ordering/comparison/endpoint/sizing/emptiness over sliced `CASE` collections lower by reducing each static-list branch to its folded scalar/list value, predicate result, endpoint, length, or emptiness value, so all-empty branches are valid for scalar reducers without rendering an untyped list. |
| Static list casts | Supported foundation | `toStringList(...)`, `toIntegerList(...)`, `toFloatList(...)`, and `toBooleanList(...)` fold literal lists, list parameters, `split(...)`, `range(...)`, `tail(...)`, static `labels(...)`, declaration-aware `keys(...)`, and other folded static-list expressions at compile time. Per-element conversion follows Cypher nullable list-cast semantics: unsupported values become `NULL`, `NULL` elements are preserved, integer-to-boolean treats zero as false and non-zero as true, and float-to-integer truncates finite values after range checks. Folded cast lists compose with projection, direct `ORDER BY` keys such as `ORDER BY range(1, 2), split('a,b', ','), toStringList([1, 2])`, static `UNWIND`, indexes/slices, `head(...)`, `last(...)`, `tail(...)`, `size(...)`, `isEmpty(...)`, exact list predicates, collection predicates, and static list comprehensions. Dynamic list values and literal `NULL` list inputs remain rejected until Coral has a nullable dynamic-list IR. |
| Static list comprehensions | Supported foundation | Parser-accepted comprehensions such as `[k IN keys(node)]`, `[l IN labels(node)]`, `[x IN ['a', 'b']]`, `[x IN $list]`, and `[x IN split('a,b', ',')]` fold through the same static-list IR as their source lists and compose with projection, `ORDER BY`, exact/ordered static-list comparisons, and `IN` right-hand sides. ## Validation

All current and future compatibility checks must use synthetic fixtures only.
Live-source tests are intentionally excluded from product validation.

The `Virtual Graph Core` workflow currently enforces two executable
compatibility baseline gates:

- `coral-opencypher-read-baseline`: 477 openCypher-style read scenarios with
  declared feature floors.
- `coral-graphql-read-baseline`: 65 GraphQL read-adapter scenarios with declared
  feature floors.

Both gates run end-to-end through parsing, graph validation, SQL lowering,
DataFusion execution, and row/error comparison. The same reporting command
emits machine-readable coverage summaries for CI step summaries.

The workflow also runs `coral-opencypher-upstream-tck-inventory`, which parses
the pinned upstream openCypher `2024.3` TCK feature tree and classifies scenario
definitions into Coral's read-only product scope. That inventory is a backlog
and credibility gate, not an execution claim: it currently reports 1,615
upstream scenario definitions, 1,294 read-candidate scenario definitions after
excluding mutations and procedure calls, and a 477-scenario Coral curated
baseline.
