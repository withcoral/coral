# Virtual Graph Compatibility Matrix

This matrix tracks production support. It is intentionally stricter than a PoC:
unsupported behavior should be rejected clearly instead of guessed.

## Declaration

| Feature | Status | Notes |
| --- | --- | --- |
| v1 YAML declarations | Supported foundation | Nodes, relationships, table refs, keys, properties |
| Duplicate label rejection | Supported foundation | One node table per graph label |
| Duplicate relationship mapping rejection | Supported foundation | Relationship mappings must have a unique `type + from label + to label` signature |
| Endpoint label validation | Supported foundation | Relationship endpoints must reference declared node labels |
| Catalog validation | Supported foundation | Checks mapped tables, columns, and required-filter constraints during explicit validation and query execution/explain |
| Multiple mappings per relationship type | Supported foundation | The validator selects the mapping by endpoint labels and direction; ambiguous undirected inverse mappings are rejected |

## Shared Graph IR

| Feature | Status | Notes |
| --- | --- | --- |
| Node scans | Supported foundation | One table per label |
| Directed relationship traversals | Supported foundation | Forward and reverse traversal lower to joins |
| Relationship type overloads | Supported foundation | A relationship type can map to multiple edge tables when endpoint labels disambiguate the pattern |
| Connected multi-hop paths | Supported foundation | Linear and closed connected patterns lower to deterministic joins |
| Disconnected mandatory patterns | Supported foundation | Disconnected mandatory node/path components lower to explicit SQL `CROSS JOIN`; disconnected patterns that include `OPTIONAL MATCH` remain rejected until optional lowering is component-aware |
| Property projections | Supported foundation | Node keys and exposed properties |
| Property predicates | Supported foundation | Literal and property-to-property comparisons with boolean expression trees |
| Numeric literals | Supported foundation | Integer and finite floating-point literals, including negated values |
| `COUNT(*)` | Supported foundation | Standalone or grouped by projected properties |
| `COUNT(property)` | Supported foundation | Counts non-null mapped property values and supported scalar expression targets such as `count(coalesce(n.tier, 'unknown'))`; optional `DISTINCT` is supported; endpoint forms such as `count(endNode(r).name)` over optional relationships are null-gated by relationship presence |
| `COUNT(node)` | Supported foundation | Counts node key occurrences; `COUNT(DISTINCT node)` counts distinct declared node keys; endpoint forms such as `count(endNode(r))` over optional relationships count only matched relationship rows |
| `COUNT(relationship)` | Supported foundation | Counts relationship rows for keyed or keyless mappings; `COUNT(DISTINCT relationship)` requires a declared relationship key |
| Collection aggregate functions | Supported foundation | `COLLECT(property)`, `COLLECT(DISTINCT property)`, `COLLECT(node)`, `COLLECT(DISTINCT node)`, keyed relationship or endpoint variants, and supported scalar expression targets such as `collect(coalesce(n.tier, 'unknown'))` lower to null-filtered DataFusion `ARRAY_AGG`; graph-variable collection returns mapped stable keys rather than materialized graph objects |
| Numeric aggregate functions | Supported foundation | `SUM`, `AVG`, `MIN`, and `MAX` over mapped graph properties, optional relationship endpoint properties such as `sum(endNode(r).risk)`, and supported scalar expression targets such as `sum(n.risk + 1)` |
| Grouped aggregate projections | Supported foundation | Property projections become SQL `GROUP BY` keys |
| Distinct projections | Supported foundation | `SELECT DISTINCT` over projected rows |
| Literal projections | Supported foundation | String, integer, finite float, boolean, null, scalar parameter literals, and non-empty homogeneous literal/list-parameter values can be projected |
| Identity projections | Supported foundation | `id(node)`, `id(keyedRelationship)`, `elementId(node)`, `elementId(keyedRelationship)`, and `type(relationship)` lower through mapped keys and fixed relationship types; `elementId` casts mapped keys to strings; optional `type(relationship)` and optional `startNode(relationship)` / `endNode(relationship)` identity expressions return null when the relationship is unmatched |
| Node label projections | Supported foundation | `labels(node)` lowers to a one-element DataFusion list containing the statically mapped node label and preserves null for unmatched optional nodes and optional relationship endpoint expressions such as `labels(endNode(r))` |
| Property key projections | Supported foundation | `keys(node)` and `keys(relationship)` lower to a deterministic list of declared graph property names and preserve null for unmatched optional bindings and optional relationship endpoint expressions such as `keys(startNode(r))` |
| Identity predicates | Supported foundation | `WHERE id(...)` compares mapped keys; `WHERE elementId(...)` compares string-cast mapped keys and rejects keyless relationships; `WHERE type(r)` is folded from the fixed relationship type |
| Ordering, skip, and limit | Supported foundation | Property order keys, identity order keys, boolean predicate scalar order keys, direct projected aggregate expressions, projection aliases including aggregate aliases, row offset, and row limit |
| Execute/explain wrappers | Supported foundation | Preserves translated SQL and diagnostics |
| Declaration-aware plan validation | Supported foundation | Resolves variables/properties and rejects unsupported plan shapes before SQL rendering |
| Optional matches | Supported foundation | Anchored optional relationship scopes lower to `LEFT JOIN`; single-hop and connected multi-hop optional chains preserve unmatched rows with nullable optional bindings; directed and undirected optional-local predicates and inline property maps lower into the nullable join scope. Later mandatory `MATCH` clauses are supported when they reference only variables bound before the optional scope; patterns or predicates that depend on optional-introduced variables remain rejected. |
| Bounded variable-length path expansion | Supported foundation | Frontends may lower finite bounded mandatory path ranges into ordinary fixed-hop branch plans. Zero-hop branches are represented as same-node key identity predicates for same-label endpoints or as statically false branches for incompatible labels. Declaration-aware Cypher expansion prunes impossible exact-hop alternatives for cross-label endpoints, keeps only unambiguous label paths, and compiles all-pruned schema ranges as empty result plans. Unbounded recursive/path expansion remains deferred. |
| Path values | Deferred | Requires graph value representation |

## Frontends

| Feature | Status | Notes |
| --- | --- | --- |
| Cypher parser | Supported foundation | `decypher` AST frontend compiles to shared IR, not directly to SQL |
| Single `MATCH ... RETURN` | Supported foundation | One non-optional MATCH clause with one or more mandatory pattern parts |
| Comma-separated `MATCH` patterns | Supported foundation | Connected parts lower to joins; disconnected mandatory parts lower to explicit SQL `CROSS JOIN` |
| Labeled node patterns | Supported foundation | Named node variables are supported; anonymous node patterns are supported when they resolve to exactly one positive static label; static exclusions such as `:Service&!Team` and grouped exclusions such as `:Service&!(Team|Legacy)` are accepted when the selected Coral mapping satisfies the full label expression, while dynamic labels, multiple required labels, and contradictory label expressions are rejected |
| Typed directed relationships | Supported foundation | Requires one positive static relationship type per expanded branch; static exclusions such as `:OWNS&!DEPENDS_ON` and grouped exclusions such as `:OWNS&!(DEPENDS_ON|ALERTS)` are accepted when the selected Coral relationship mapping satisfies the full type expression, while dynamic types, multiple required types, and contradictions are rejected. Exact-one relationship ranges/quantifiers such as `*1`, `*1..1`, `{1}`, and `{1,1}` are accepted as single-hop syntax compatibility |
| Static pattern label/type alternatives | Supported foundation | Row-preserving single-query patterns such as `(n:Person|Team)` and `-[r:OWNS|DEPENDS_ON]->` expand to `UNION ALL` branches with a capped branch count. Final `RETURN DISTINCT`, standalone or grouped `count(*)`, grouped `count(property)`, `count(variable)`, `count(DISTINCT variable)`, `collect(property)`, numeric/statistical property aggregates such as `sum(n.score)` or `avg(n.score)`, aggregate scalar expression targets such as `collect(coalesce(n.tier, 'unknown'))` and `sum(n.score + 1)`, projected-expression or alias `ORDER BY`, row-preserving hidden `ORDER BY` expressions, `SKIP`, and `LIMIT` are applied after the expanded union. Distinct graph-variable counts use an internal label/type-qualified graph identity so keys from different mapped tables do not collide. Row-preserving alternatives can be flattened inside explicit top-level `UNION ALL`. Queries with correlated subqueries inside aggregate expression targets, hidden ordering for aggregate or `RETURN DISTINCT` alternatives, `WITH DISTINCT`, `WITH ORDER BY`/`SKIP`/`LIMIT`, explicit top-level `UNION` distinct, or branch-level alternative modifiers inside explicit `UNION ALL` remain rejected until Coral has broader staged outer-query planning. |
| Undirected relationships | Supported foundation | Lowers to orientation-aware joins; same-label relationships use disjunctive endpoint conditions; inverse overloaded mappings that both match are rejected as ambiguous. `startNode(r)` and `endNode(r)` over cross-label undirected relationships use the single matching graph declaration mapping to recover original edge orientation; same-label or ambiguous undirected endpoint functions remain rejected because start/end is data-dependent. |
| Multi-hop relationship chains | Supported foundation | Forward, reverse, and mixed chains compile through the shared graph IR |
| Multiple `MATCH` clauses | Supported foundation | Transparent multi-part read clauses compile into one connected graph plan |
| `WHERE` property comparisons | Supported foundation | String, integer, float, boolean, null literal, property-to-property comparisons, and scalar-expression RHS comparisons |
| `WHERE id(...)` predicates | Supported foundation | Node ids and keyed relationship ids lower to mapped key comparisons and `IN` predicates |
| `WHERE type(r)` predicates | Supported foundation | Folded to boolean predicates because each relationship pattern has one static type; equality, inequality, `IN`, `STARTS WITH`, `ENDS WITH`, `CONTAINS`, and regex matching are supported |
| `WHERE node:Label` / `relationship:TYPE` predicates | Supported foundation | Static label/type expressions fold against the mapped node label or relationship type, including grouped conjunction/disjunction/negation; dynamic labels remain rejected |
| Chained comparisons | Supported foundation | Normalized to conjunctions, e.g. `10 <= n.score < 20` |
| Literal-left comparisons | Supported foundation | Operators are inverted around the property operand where possible |
| Literal-only predicates | Supported foundation | Non-null literal comparisons, including ordered numeric and string comparisons, and literal `IN` membership fold to boolean predicates; null-producing unknown cases are rejected instead of guessed |
| `WHERE` boolean logic | Supported foundation | `AND`, `OR`, `XOR`, `NOT`, and parentheses lower to SQL boolean predicates; `XOR` is rendered as a null-preserving boolean rewrite instead of relying on target-specific SQL syntax |
| `WHERE ... IN [...]` | Supported foundation | Literal scalar lists, including numeric and null members, lower to SQL `IN`; empty lists lower to `FALSE`. Static folded list expressions such as `property IN (['prod'] + $tiers)`, `property IN keys(optionalNode)`, and `property IN (keys(optionalNode) + ['extra'])` are supported as RHS values; optional graph bindings preserve unmatched rows as `NULL` through presence gating. List-comprehension RHS forms after `IN` are still parser-limited and should be expressed as supported folded-list forms until the parser frontend accepts them. |
| `WHERE '<Label>' IN labels(node)` | Supported foundation | String-literal and scalar string parameter membership predicates fold against the statically mapped node label; optional relationship endpoint forms preserve optional-match null semantics |
| `WHERE '<key>' IN keys(variable)` | Supported foundation | String-literal and scalar string parameter membership predicates lower against declared graph property metadata; optional relationship endpoint forms preserve optional-match null semantics |
| `WHERE labels(node) = [...]` / `keys(variable) = [...]` / `tail(list) = [...]` | Supported foundation | Declaration-aware equality, inequality, and lexicographic ordered comparisons against literal lists, list parameters, `tail(...)`, or other static list expressions fold from static node-label and declared-property metadata. Reversed operands such as `['Service'] = labels(node)`, `[] = tail(labels(node))`, and `['Team'] > labels(node)` are supported. Ordered comparisons require compatible string or numeric folded-list element families; boolean and cross-family ordered lists are rejected. Optional node and relationship endpoint forms preserve null semantics through the same presence-gated scalar IR used by metadata projections, and null element comparisons fold to Cypher unknown. |
| `all` / `any` / `none` / `single` collection predicates | Supported foundation | Static collection predicates such as `all(k IN keys(node) WHERE k != 'deprecated')`, `any(k IN tail(keys(node)) WHERE k = 'tier')`, `any(k IN keys(node) WHERE k > 'team')`, `none(label IN labels(node) WHERE label = 'Team')`, and predicates over literal or list-parameter collections fold at compile time. Supported item predicates include the filter variable, literals, scalar parameters, equality/inequality, ordered numeric and string comparisons, string predicates (`STARTS WITH`, `ENDS WITH`, `CONTAINS`, and regex), `IN` against static lists, `IS NULL`, and `AND`/`OR`/`XOR`/`NOT`. Optional graph metadata collections preserve null semantics with presence-gated boolean scalars, and null-sensitive item outcomes preserve Cypher unknown semantics. Dynamic collections remain rejected. |
| Static list indexes | Supported foundation | Positive and negative integer indexes over folded static lists, including `labels(...)`, declaration-aware `keys(...)`, `tail(...)`, `reverse(...)`, and static list concatenation, fold at compile time in projections, predicates, searched `CASE WHEN`, and `ORDER BY`; out-of-range indexes fold to `NULL`. Optional node and endpoint forms preserve null semantics through presence-gated scalar IR. Dynamic list indexing remains rejected. |
| Static list slices | Supported foundation | Start-inclusive/end-exclusive slices over folded static lists, including `labels(...)`, declaration-aware `keys(...)`, `tail(...)`, `reverse(...)`, and static list concatenation, fold at compile time in projections, equality predicates, `size(...)`, `isEmpty(...)`, nested indexes, and `ORDER BY`. Optional node and endpoint forms preserve null semantics through presence-gated list scalar IR. Empty projected slices are supported by carrying a typed folded-list expression through the IR and rendering typed empty arrays in DataFusion SQL. |
| `head(list)` / `last(list)` / `tail(list)` | Supported foundation | Literal lists, list parameters, and static `labels(...)` / declaration-aware `keys(...)` metadata lists fold at compile time in projections, predicates, searched `CASE WHEN`, and `ORDER BY`; empty matched lists fold to `NULL` for `head(...)` / `last(...)`, while optional node and endpoint metadata preserves unmatched rows as `NULL`. `tail(...)` returns typed folded lists, including empty tails, and composes with `head(...)`, `last(...)`, `size(...)`, and `isEmpty(...)` when the input list has a known non-null element type. Ambiguous empty, all-null, or mixed-type list-valued `tail(...)` results are rejected. Dynamic list values remain rejected. |
| Static list `reverse(list)` | Supported foundation | List-valued `reverse(...)` folds literal lists, list parameters, `tail(...)`, static `labels(...)`, declaration-aware `keys(...)`, and static list concatenation at compile time. Folded reverse composes with projection, `ORDER BY`, `head(...)`, `last(...)`, `tail(...)`, `size(...)`, `isEmpty(...)`, exact list equality/inequality, static collection predicates, and optional graph metadata presence gates. String-valued `reverse(scalar)` still lowers as a normal scalar string function. Ambiguous empty, all-null, or mixed-type list-valued results are rejected. |
| Static list concatenation | Supported foundation | `+` concatenates foldable static lists from literal lists, list parameters, `tail(...)`, `labels(...)`, and declaration-aware `keys(...)`. Concatenated lists compose with projection, `ORDER BY`, `head(...)`, `last(...)`, `tail(...)`, `size(...)`, `isEmpty(...)`, exact list equality/inequality, static `all`/`any`/`none`/`single`, and parenthesized `IN` RHS expressions. Nullable metadata lists on the right-hand side of `IN` preserve optional-match nulls through presence gating. Mixed element types, dynamic operands, projected all-null/empty unknown element types, and lists from different optional bindings are rejected. |
| Static list comprehensions | Supported foundation | Parser-accepted comprehensions such as `[k IN keys(node)]`, `[l IN labels(node)]`, `[x IN ['a', 'b']]`, and `[x IN $list]` fold through the same static-list IR as their source lists and compose with projection and `ORDER BY`. Static `WHERE` filters over the item variable, literals, scalar parameters, equality/inequality, ordered numeric and string comparisons, string predicates (`STARTS WITH`, `ENDS WITH`, `CONTAINS`, and regex), folded scalar operands such as `toIntegerOrNull(x) >= 2`, `x + 1 > 3`, or `isEmpty(x) = false`, `isEmpty(...)` over strings or static lists, `IN` static lists, `IS NULL`, and `AND`/`OR`/`XOR`/`NOT` are folded before SQL lowering, so forms such as `[k IN keys(node) WHERE k STARTS WITH 't']`, `[k IN keys(node) WHERE toUpper(k) STARTS WITH 'T']`, `[x IN ['', 'a'] WHERE isEmpty(x)]`, `[x IN ['', 'a'] WHERE isEmpty(x) = false]`, `[k IN keys(node) WHERE k > 'risk']`, and `[x IN $list WHERE x IN keys(node)]` are supported. Static map expressions over the item variable support identity, scalar literals, scalar parameters, numeric arithmetic, predicate-valued maps including `isEmpty(...)`, `coalesce(...)`, `nullIf(...)`, `size(...)`/`char_length(...)`, strict and nullable scalar casts such as `toInteger(...)` and `toIntegerOrNull(...)`, numeric `abs(...)`, `ceil(...)`/`ceiling(...)`, `floor(...)`, `round(...)`, `sqrt(...)`, and `sign(...)`, string case conversion, trim variants, `replace(...)`, `substring(...)`, `left(...)`, `right(...)`, and scalar-string `reverse(...)`, enabling forms such as `[x IN [1, 2] | x + 1]`, `[k IN keys(node) | k STARTS WITH 't']`, `[k IN keys(node) | coalesce(null, k)]`, `[k IN keys(node) | nullIf(k, 'id')]`, `[k IN keys(node) | size(k)]`, `[x IN ['1', 'bad'] | toIntegerOrNull(x)]`, `[x IN [1, 3, 5] | sign(x - 3)]`, `[x IN [1.24, 1.25] | round(x, 1)]`, `[k IN keys(node) WHERE k != 'id' | replace(k, '_', '-')]`, and `[k IN keys(node) | left(k, 2)]`. Dynamic source collections are rejected. |
| `size(labels(node))` / `size(keys(variable))` | Supported foundation | Metadata list lengths fold at compile time in projections, predicates, searched `CASE WHEN`, and `ORDER BY`; optional node and endpoint forms preserve null semantics through presence-gated scalar IR. Integer constants in `ORDER BY` are rendered as casts so DataFusion does not interpret them as select-list ordinals. |
| Cypher parameters | Supported foundation | Explicit typed parameter API binds scalar values in literal positions and list values as `IN` right-hand sides or exact metadata-list comparison operands before SQL lowering |
| `WHERE ... STARTS WITH` / `ENDS WITH` / `CONTAINS` | Supported foundation | String-literal and string-parameter RHS lowers to escaped SQL `LIKE`; scalar expression RHS lowers to DataFusion `starts_with`, `ends_with`, and `contains` |
| `WHERE ... =~` regex matching | Supported foundation | String-literal, string-parameter, and scalar expression RHS lowers to DataFusion `regexp_like`; semantics follow DataFusion/Rust regex rather than Neo4j's Java regex dialect |
| `WHERE ... IS NULL` / `IS NOT NULL` | Supported foundation | Lowers to SQL `IS NULL` / `IS NOT NULL` |
| `WHERE EXISTS { ... }` | Supported foundation | Compact pattern predicates such as `EXISTS { (a)-[:REL {source: 'catalog'}]->(b:Service {tier: 'prod'}) }`, compact scoped predicates such as `EXISTS { (a)-[:REL]->(b:Service) WHERE b.tier = 'prod' }`, and explicit `EXISTS { MATCH ... WHERE ... }` subqueries lower to SQL semi-joins. Inline property maps, compact pattern `WHERE`, and explicit subquery `WHERE` clauses support property comparisons joined by `AND`; broader scoped boolean expressions, `OPTIONAL MATCH`, `WITH`, `RETURN`, and `UNION` inside existential subqueries remain rejected until staged subquery planning is available. |
| Inline node property maps | Supported foundation | Normalized to equality predicates, e.g. `(n:Service {tier: 'prod'})`; scalar parameter values such as `(n:Service {tier: $tier})` bind through the typed Cypher parameter API before SQL lowering |
| Inline relationship property maps | Supported foundation | Anonymous relationships get internal variables for property predicates; scalar parameter values such as `[:OWNS {source: $source}]` bind through the typed Cypher parameter API |
| `RETURN` property projections | Supported foundation | Optional aliases are supported |
| `RETURN *` over graph variables | Supported foundation | Runtime `execute_cypher` / `explain_cypher` and declaration-aware compile APIs expand visible graph variables from the graph declaration into deterministic tabular columns: `variable.__id`, `variable.__labels` for nodes, `relationship.__id` when the relationship mapping declares a key, `relationship.__type`, and mapped properties as `variable.property`. Star expansion may be followed by explicit projections such as `RETURN *, n.score AS score`. Internal planner variables are hidden, transparent `WITH` scope is respected, and path variables are rejected because Coral does not materialize graph objects or path values yet. Declaration-free compile helpers reject `RETURN *` because they cannot know mapped properties. |
| `RETURN variable` graph-object projections | Supported foundation | Declaration-aware Cypher compilation expands a visible node or relationship variable into the same deterministic tabular columns used by `RETURN *`; `RETURN service AS svc` prefixes output columns as `svc.__id`, `svc.__labels`, and `svc.property`. Path variables remain rejected because path values are not materialized. |
| `RETURN` literal projections | Supported foundation | Supports string, integer, finite float, boolean, null, scalar parameters, non-empty homogeneous literal/list-parameter lists, compile-time indexing over literal lists or list parameters, and non-empty compile-time slices over literal lists or list parameters. Empty, all-null, and mixed-type list projections are rejected; out-of-range list indexes fold to `NULL`. |
| `RETURN` / `ORDER BY` / `WHERE` scalar expressions | Supported foundation | Arithmetic `+`, `-`, `*`, `/`, `%`, and `^`, unary numeric negation, boolean predicate scalar expressions in `RETURN` and `ORDER BY`, searched `CASE WHEN ... THEN ... ELSE ... END`, generic `CASE expr WHEN value THEN ... ELSE ... END`, plus `coalesce(...)`, `nullIf(...)`, strict casts `toString(...)`, `toInteger(...)`, `toFloat(...)`, `toBoolean(...)`, nullable casts `toStringOrNull(...)`, `toIntegerOrNull(...)`, `toFloatOrNull(...)`, `toBooleanOrNull(...)`, string case/trim/replace functions including GQL-style `lower(...)`, `upper(...)`, and `btrim(...)` aliases, `head(...)`, `last(...)`, `tail(...)`, `size(...)`/`char_length(...)`/`character_length(...)`, `substring(...)`, `left(...)`, `right(...)`, `reverse(...)`, numeric `abs(...)`, `ceil(...)`/`ceiling(...)`, `floor(...)`, `round(value[, places])`, `sqrt(...)`, `sign(...)`, `exp(...)`, `log(...)`/`ln(...)`, `log10(...)`, constants `pi()` and `e()`, trigonometric `sin(...)`, `cos(...)`, `tan(...)`, `cot(...)`, `asin(...)`, `acos(...)`, `atan(...)`, `atan2(y, x)`, `degrees(...)`, `radians(...)`, and `haversin(...)`, plus graph metadata `id(variable)`, `elementId(variable)`, and `type(relationship)` over graph properties, scalar literals, scalar parameters, and nested supported scalar expressions. `id(variable)` keeps the mapped key's native type; `elementId(variable)` lowers to a string cast and requires keyed relationships; `type(relationship)` lowers to the static relationship type. Runtime execute/explain validates catalog-known scalar types before SQL planning, so mixed `coalesce`/CASE branches, string functions over numeric values, numeric functions over strings, arithmetic over non-numeric values, and incompatible scalar/direct predicate operands fail with `INVALID_SCALAR_TYPE`; pure translation without a runtime catalog remains conservative for unknown property types. Metadata scalar expressions are valid in forms such as `toString(id(n))`, `coalesce(elementId(r), 'missing')`, `coalesce(type(r), 'missing')`, `coalesce(endNode(r).name, 'missing')`, `labels(endNode(r))`, `keys(startNode(r))`, `labels(n)[0]`, `keys(r)[-1]`, `labels(n)[0..1]`, `keys(r)[1..][0]`, `head(labels(n))`, `last(keys(r))`, `tail(keys(n))`, `reverse(keys(n))`, `head(tail(keys(n)))`, `size(labels(n))`, `size(tail(keys(r)))`, `labels(n) + keys(n)`, CASE result branches, scalar predicates, and `ORDER BY`, preserving `NULL` for unmatched optional relationships. Boolean predicate scalar expressions include comparisons, `IN`, null checks, static label/type predicates, metadata-list equality/inequality, static list reverse, static list concatenation, static `all`/`any`/`none`/`single` collection predicates, metadata-list indexes, metadata-list slices, metadata-list endpoint functions, and metadata-list sizes for `labels(...)` and declaration-aware `keys(...)`, `exists(property)`, a single correlated `EXISTS { MATCH ... }` or `COUNT { MATCH ... }` inside a scalar projection or searched CASE expression, `isEmpty(scalar)`, `isEmpty(labels(...))`, declaration-aware `isEmpty(keys(...))`, `isEmpty(tail(keys(...)))`, and `AND`/`OR`/`XOR`/`NOT`. Correlated scalar subqueries may be sorted by projected alias or by repeating the exact projected scalar expression, which is resolved to the alias; hidden direct `ORDER BY` over unprojected correlated subqueries and multiple correlated `COUNT`/`EXISTS` subqueries inside one scalar projection are rejected with guidance to project each subquery separately. `nullIf(a, b)` lowers to DataFusion SQL `NULLIF(a, b)`. Strict casts lower to DataFusion `CAST`; nullable casts lower to `TRY_CAST`. Cypher `log(...)` and GQL-style `ln(...)` lower to DataFusion `ln(...)` to preserve natural-log semantics; `pi()` and `e()` compile to deterministic float literals; `haversin(x)` lowers as `(1 - cos(x)) / 2`. Scalar-string `isEmpty(expr)` is supported as a predicate in `WHERE` and searched `CASE WHEN`, lowering to `char_length(expr) = 0`; `isEmpty(labels(...))`, `isEmpty(tail(...))`, metadata-list slices, static list reverse, and static list concatenation fold from static metadata when available; all preserve `NULL` for unmatched optional endpoint metadata. `head(...)`, `last(...)`, `tail(...)`, `reverse(...)`, `size(...)`, `isEmpty(...)`, zero-based positive or negative index expressions, and start-inclusive/end-exclusive slices over literal lists and list parameters are folded at compile time; metadata-list endpoint functions, sizes, indexes, slices, typed empty-list outputs, static list reverse, static list concatenation, and static collection predicates are also folded from static graph metadata. Dynamic list, map, and path values are not modeled yet. CASE `WHEN` predicates support property/scalar comparisons, `IN` literal lists, exists(property), `isEmpty(scalar)`, graph variable/id/elementId null checks, static label/type predicates, literal membership, exact list equality/inequality, static collection predicates, static list reverse, static list concatenation, head, last, tail, size, slice, and index expressions in `labels()` / `keys()` including optional relationship endpoints, `type(relationship)` comparisons and `IN`, scalar null checks, and `AND`/`OR`/`XOR`/`NOT`; projected and ordered CASE expressions may reference unmatched optional bindings and follow SQL null/unknown semantics without filtering rows. |
