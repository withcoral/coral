## Supported data source types

SourceSpec supports four interface kinds.

- **OpenAPI** — Coral snapshots REST provider operations and derives capabilities.
- **Upstream MCP** — Coral snapshots provider `tools/list` and derives tool capabilities.
- **GraphQL** — Coral imports SDL or introspection and generates bounded root-field capabilities.
- **File** — Coral imports explicit read-only JSON, JSONL, CSV, or Parquet file relations.

## Upgrading bundled sources

To update active bundled sources, upgrade the Coral binary. Installed source identity, variables, and secrets stay in local state. Generated capability/export artifacts are materialized at source add; re-add the source when the bundled SourceSpec or provider snapshot should be regenerated.

## Configure a source

Each source has its own set of interactive inputs — API tokens, base URLs, or
other per-install configuration.

### `datadog`

`DD_API_KEY` (required)

Datadog API key. Coral sends it as DD-API-KEY for REST calls and DD_API_KEY for Datadog MCP calls.

`DD_APPLICATION_KEY` (required)

Datadog application key with access to the Datadog resources you want Coral to query. Coral sends it as DD-APPLICATION-KEY for REST calls and DD_APPLICATION_KEY for Datadog MCP calls.

`DD_SITE` (required)<br />
default `datadoghq.com`

Datadog site host for your org, such as datadoghq.com, datadoghq.eu, us3.datadoghq.com, us5.datadoghq.com, ap1.datadoghq.com, or ap2.datadoghq.com. The Datadog MCP Server does not support GovCloud sites.

### `github`

`GITHUB_TOKEN` (required)

GitHub personal access token or OAuth bearer token. Coral sends it as an Authorization bearer token for GitHub REST, GraphQL, and MCP calls.

### `linear`

`LINEAR_API_KEY` (required)

Personal Linear API key. Coral sends it as the raw Authorization header value for GraphQL and as an Authorization bearer token for Linear MCP calls.

### `slack`

`SLACK_USER_TOKEN` (required)

User OAuth token for Slack's hosted MCP server. Install interactively to authorize with Slack OAuth, or set this to an existing user token.

Credential methods:

- **Connect with Slack** — The Slack app must be internal or directory-published, have MCP access and PKCE enabled, and allow the redirect URL http://localhost:53682/oauth/callback.
